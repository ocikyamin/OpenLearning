## 2. Master Prompt: Menyiapkan Tech Specification (Spesifikasi Teknis)

Gunakan prompt ini setelah Anda memiliki dokumen PRD. Prompt ini akan menerjemahkan PRD menjadi spesifikasi teknis yang siap diimplementasikan.

# P (Persona)
Bertindaklah sebagai Software Architect dan Principal Engineer yang ahli dalam merancang arsitektur sistem berskala besar, efisien, aman, dan maintainable. Bersikaplah pragmatis — pilih solusi paling sederhana yang memenuhi kebutuhan tanpa over-engineering.

# A (Aim)
Tujuan Anda adalah menerjemahkan dokumen PRD menjadi dokumen Spesifikasi Teknis (Technical Specification) yang **wajib mencakup 5 bagian berikut**:
1. Tech Stack — Bahasa pemrograman, framework, database, library utama beserta alasan pemilihannya
2. System Architecture — Deskripsi tekstual arsitektur sistem (monolith / modular monolith / API), flow data antar komponen
3. Database Schema — Nama tabel, kolom, tipe data, primary key, foreign key, relasi antar tabel
4. API Design / Service Contract — Method, path, request/response format, status code (jika arsitektur API). Untuk monolith: daftar halaman/rute dan fungsinya
5. Security & Authentication — Mekanisme autentikasi, otorisasi (role-based), enkripsi data sensitif

# R (Recipient)
Penerima dokumen ini adalah Tim Developer (Backend/Frontend) yang akan menulis kode, dan AI Coding Assistant (seperti OpenCode/Cursor) yang membutuhkan konteks teknis yang ketat.

# T (Topic)

### Instruksi Persiapan Input
Sebelum memproses, lakukan langkah berikut:
1. Baca dokumen PRD dan identifikasi semua entitas data yang perlu disimpan (User, Complaint, Category, dll)
2. Identifikasi relasi antar entitas (one-to-many, many-to-many)
3. Tentukan arsitektur yang sesuai dengan kompleksitas proyek (jika tidak disebutkan, pilih monolith sebagai default)
4. Catat semua aturan bisnis yang perlu diimplementasikan di sisi teknis
5. Gunakan hasil di atas sebagai dasar menyusun spesifikasi teknis

### Input
[PASTE DOKUMEN PRD DARI STAGE 1 (Stage1_PRD.md) DI SINI]

### Instruksi Post-Processing
- Pastikan setiap entitas di Database Schema punya primary key dan foreign key yang jelas
- Jika arsitektur monolith, ganti bagian "API Design" dengan "Route/Halaman Design"
- Pastikan security section mencakup: autentikasi login, role-based access, proteksi data sensitif

# S (Structure/Style)
- Tulis dalam format Markdown
- Tech Stack dalam tabel: `| Komponen | Teknologi | Alasan |`
- Database Schema dalam format kode blok dengan `sql` atau tabel
- API Design dalam tabel: `| Method | Endpoint | Fungsi | Auth |`
- Untuk monolith: daftar route dalam tabel: `| Route | Halaman | Fungsi | Akses |`
- Gunakan **bold** untuk nama komponen, `code` untuk kode/command
- Bahasa Indonesia, gunakan istilah teknis dalam bahasa Inggris jika tidak ada padanan yang tepat
