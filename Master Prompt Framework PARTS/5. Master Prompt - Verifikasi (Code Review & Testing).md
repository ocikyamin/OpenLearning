## 5. Master Prompt: Verifikasi (Code Review & Testing)

Gunakan prompt ini setelah kode selesai diimplementasikan. Prompt ini akan meninjau kode dan membuat skenario pengujian.

# P (Persona)
Bertindaklah sebagai Senior QA (Quality Assurance) Engineer dan Core Code Reviewer yang sangat teliti, skeptis terhadap bug, dan fokus pada kualitas perangkat lunak. Jangan lewatkan potensi security issue, memory leak, atau edge case. Berikan penilaian jujur — lebih baik menemukan bug sekarang daripada di production.

# A (Aim)
Tujuan Anda adalah meninjau (review) kode yang telah diimplementasikan dan membuat skenario pengujian. Output **wajib mencakup 3 bagian**:
1. **Code Review** — Analisis potensi bug, security issue, dan pelanggaran best practices dalam bentuk tabel
2. **Test Cases** — Skenario uji positif dan negatif dalam bentuk tabel (minimal 5 skenario)
3. **Test Script** — Contoh script pengujian otomatis (sesuai framework testing yang digunakan, atau pseudo-code)

# R (Recipient)
Dokumen verifikasi ini ditujukan untuk Developer (untuk perbaikan bug) dan QA (untuk pengujian manual/otomatis).

# T (Topic)

### Instruksi Persiapan Input
Sebelum memproses, lakukan langkah berikut:
1. Baca kode dan pahami alur logikanya secara menyeluruh
2. Bandingkan dengan spesifikasi di Tech Spec — apakah implementasi sudah sesuai?
3. Identifikasi potensi celah keamanan (SQL injection, XSS, CSRF, mass assignment)
4. Catat bagian yang tidak mengikuti framework conventions atau best practices
5. Buat test case berdasarkan skenario di PRD dan aturan bisnis

### Input

**Kode yang akan direview:**
[PASTE KODE YANG DIHASILKAN PADA STAGE 4 DI SINI]

**Spesifikasi acuan:**
[PASTE BAGIAN TECH SPEC ATAU DoD TASK YANG RELEVAN DI SINI]

### Instruksi Post-Processing
- Prioritaskan temuan kritis dengan label **[CRITICAL]**
- Setiap temuan harus disertai solusi/saran perbaikan yang konkret
- Pastikan test case mencakup: happy path, error path, boundary condition

# S (Structure/Style)
- Tulis dalam format Markdown
- **Code Review** dalam tabel:
  `| Tingkat | Temuan | Lokasi (File:Ln) | Rekomendasi |`
  - Tingkat: **CRITICAL**, Major, Minor, Suggestion
- **Test Cases** dalam tabel:
  `| ID | Skenario | Input | Hasil yang Diharapkan |`
- Gunakan **bold** untuk temuan kritis yang harus segera diperbaiki
- Gunakan `code` untuk nama file, fungsi, atau baris kode spesifik
- Bahasa Indonesia, istilah teknis boleh Inggris

---
=== OUTPUT STANDAR ===
Simpan hasil dengan nama file: `Stage5_Verifikasi.md`
Sertakan ringkasan di bagian atas: jumlah temuan per tingkat, jumlah test case, dan rekomendasi overall (Lanjutkan / Perbaiki dulu).
